# TypeScript CLI 구현 계획

현재 설정·역할·스킬은 Codex가 수행하는 작업 절차다. CLI 구현은 같은 [데이터 계약](data-contracts.md)을 사용하며 단계적으로 자동화한다.

## 1. 실행 기반

- Node.js·pnpm 버전을 고정하고 `package.json`, `pnpm-lock.yaml`, TypeScript `strict`·ESM, ESLint·Prettier·Vitest 설정을 추가한다.
- `src/cli`, `src/workflows`, `src/domain`, `src/integrations`, `src/storage`를 필요한 기능부터 만든다.
- `dev`, `build`, `typecheck`, `lint`, `format:check`, `test` 스크립트를 정의하고 문서의 제안 명령을 실제 실행 결과로 갱신한다.

완료 기준: 빈 기능 골격만으로 완료 처리하지 않고, 합성 입력으로 상태·파일 저장까지 실행되는 최소 명령을 제공한다.

## 2. 이력서 가져오기

- 로컬 입력을 먼저 지원하고, Drive 검색·메타데이터·내보내기는 교체 가능한 어댑터로 추가한다.
- MIME 타입별 추출기를 분리하고 Zod로 `profile.json`과 `run.json`을 검증한다.
- 원본 보존, 파일 버전 추적, 근거 위치, 추출 실패·빈 문서 구분을 구현한다.

완료 기준: 익명화한 DOCX/PDF fixture로 사실·근거·미확인 항목을 생성하고 원본이 변하지 않는다.

## 3. 공고 조사와 매칭

- 검색·상세 확인·필터링·근거 매칭을 분리한다. 최초에는 제공받은 공고 데이터로 검증하고 실사이트 어댑터를 연결한다.
- 공식 API 발급 시 해당 어댑터를 우선 사용하고, 브라우저 연결은 사이트 구조 변경·로그인·접근 실패를 결과로 표현한다.
- 필수·우대 조건, 모집 상태, 날짜, 중복 제거와 `unknown` 처리를 구현한다.

완료 기준: 합성 프로필·공고에서 추천 근거를 재현하고, 마감·미확인 공고를 모집 중으로 오인하지 않는다.

## 4. 문서 수정

- 원본에서 별도 수정본을 만들고 사실 근거와 편집 표현을 구분한다.
- DOCX/PDF 도구를 어댑터로 연결하고 변경 요약·렌더링 검증 결과를 저장한다.
- Drive 업로드는 요청 범위와 원격 결과를 기록해 재실행 시 중복을 방지한다.

완료 기준: 수정본·변경 요약·미리보기를 제공하고, 미확인 성과나 경력을 추가하지 않는다.

## 5. 독립 실행이 필요해질 때

MCP 연결·OAuth·모델 호출을 독립 CLI에 구현한다. 호스트 커넥터를 암묵적으로 재사용하지 않는다. 사용자가 선택한 모델과 데이터 전달 범위를 유지하며, 로컬 fixture 검증과 실제 계정 연동 검증을 분리한다.
