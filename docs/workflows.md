# 작업 흐름과 역할 분배

## 공통 실행 방식

부모 에이전트가 요청 범위·입력·사용 가능 도구를 확인하고 [데이터 계약](data-contracts.md)에 맞는 실행 디렉터리를 만든다. 단순 작업은 직접 처리하고, 독립된 조사가 있으면 역할 에이전트에 배정한다. 역할 이름 자체가 자동 실행 순서를 만들지는 않는다.

| 역할 | 입력 | 담당 산출물 |
| --- | --- | --- |
| `resume_analyst` | 확정된 Drive 파일 또는 로컬 원본 | `profile.json`, 원본 사본과 근거 |
| `job_researcher` | 프로필의 필요한 기술·경력과 희망 조건 | `jobs.json`; 배정받은 경우 `matches.json`, `report.md` |
| `resume_editor` | 원본, 수정 요청, 선택적 목표 공고 | 수정본, `edits.md` |
| `reviewer` | 배정된 문서·데이터·변경 사항 | 부모에게 검토 결과 반환; 파일은 직접 수정하지 않음 |

부모만 `run.json`을 갱신한다. 각 자식에게 입력 경로·출력 경로·완료 조건·수정 가능 파일을 지정한다. 같은 파일을 두 작업에 배정하지 않는다. 최종 통합과 리뷰 결과 기록은 부모가 담당한다.

## 이력서 가져오기: `$resume-intake`

1. Drive URL/ID나 로컬 파일을 확인한다. 원본이 여러 개면 사용할 파일을 확정한다.
2. 원본을 별도 보존하고 파일 버전·추출 방법을 기록한다.
3. 경력·기술·프로젝트 사실에 원본 위치를 연결해 `profile.json`을 작성한다. 연락처 등 추천에 불필요한 정보는 프로필에서 제외한다.
4. 읽을 수 없는 표·이미지·기간은 미확인으로 남긴다. 프로필 요약과 누락 항목을 제공한다.

완료 기준: 원본 추적이 가능하고 추출한 사실에 근거가 있다. 텍스트 추출 실패를 빈 이력서로 처리하지 않는다.

## 공고 탐색: `$job-search`

1. 사용할 프로필과 요청 조건을 확인한다. 새 실행에서 이전 프로필을 재사용하면 원본 변경 여부를 확인하고 실행 디렉터리에 `profile.json` 사본을 둔다. `.local/preferences.json`이 있으면 읽되 이번 요청의 조건을 우선한다.
2. 새 후보 수집이 요청되면 직무·기술·지역으로 공개 검색을 수행한다. 검색어에 이력서 전체·연락처를 포함하지 않는다. 제공된 공고 본문만 비교하는 요청은 검색·외부 조회를 생략한다.
3. 상세 페이지, 발급받은 공식 API 또는 사용자 제공 본문으로 사실을 확인해 `jobs.json`을 작성하고 확인 방식을 기록한다. 공고 ID/URL로 중복을 구분한다.
4. 필수·우대 조건별로 프로필 근거를 연결하고 `met`, `not_met`, `unknown`을 구분한다. 이력서에 없다는 이유만으로 경험이 없다고 단정하지 않는다.
5. 확인 시각·모집 상태·적합한 점·부족한 점·불확실성을 `report.md`에 제시한다. 목표 건수를 채우려고 마감·미확인 공고를 모집 중으로 취급하지 않는다.

독립된 공고 묶음은 병렬 조사할 수 있다. 이 경우 부모가 각각 다른 임시 파일 경로를 지정하고, 수집 후 `jobs.json`으로 통합한다. 동일 브라우저 프로필을 동시에 조작하지 않는다.

제공 본문만 비교하는 요청은 해당 범위의 검증을 마치면 완료할 수 있다. 다만 현재 모집 상태를 확인한 것처럼 표현하지 않는다. 모집 중인 새 공고를 찾아 달라는 요청에서 최신 상태 확인이 빠졌다면 미완료 범위로 남긴다.

## 이력서 수정: `$resume-tailor`

1. 수정 대상과 원하는 결과를 확인한다. 목표 공고는 선택 사항이며 일반적인 문장·구성 수정도 지원한다.
2. 사실과 편집 표현을 구분하고 `revised/`에 새 버전을 작성한다. 원본을 덮어쓰지 않는다.
3. 변경 이유와 원본 근거를 `edits.md`에 기록한다. 필요한 경험·수치가 없으면 확인 사항으로 남긴다.
4. DOCX/PDF 결과는 렌더링으로 잘림·표·페이지 나눔을 확인한다. 관련 도구가 없으면 검증 한계를 기록하고 편집 가능한 초안을 제공한다.

업로드·원본 반영·지원서 제출은 해당 대상과 범위에 대한 사용자 요청이 있을 때 수행한다. 이미 요청한 작업에 대한 재승인을 반복하지 않는다.

## 상태와 재개

- `completed`: 요청한 단계의 산출물과 해당 검증이 완료됨.
- `partial`: 일부 유효한 결과가 있으나 요청 범위에 미완료·미확인 항목이 남음.
- `blocked`: 입력 선택·인증·도구·접근 권한 등 해당 단계의 선행 조건이 없음.
- `failed`: 시도한 처리가 실패했고 사용할 결과를 만들지 못함.

조회 실패는 범위를 줄여 재시도할 수 있다. 반복되는 같은 오류를 무제한 재시도하지 않는다. 외부 쓰기의 결과가 불명확하면 원격 상태를 조회한 뒤 다음 작업을 결정하며 업로드·수정을 곧바로 반복하지 않는다.

재개 시 원본의 ID·수정일 또는 해시와 희망 조건을 확인한다. 바뀌었다면 관련 결과를 다시 만들고, 그대로라면 완료 단계는 재사용한다. 공고의 모집 상태는 보고 직전에 다시 확인한다. 단계가 막혀도 독립적으로 진행 가능한 작업은 계속한다.
